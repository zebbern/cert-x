# Compare accounts — implementation contract

Separate read-access workflow; existing injection plans stay unchanged. Reuse `kiDastCompanion` authenticated RPC with `authz_*` operations. Private account material and plans live in `chrome.storage.session`; public account metadata and terminal batch summaries may persist locally. Credentials never enter model tool results, page scripts, approval previews or reports.

## Companion wire (revision 4)

- `authz_verify`: `{owner, account, scope, origin, tabId, budget}`; return verified/inconclusive and safe reason, never response body or credentials.
- `authz_run`: `{batchId, owner, workspaceId, origin, tabId, scope, budget, accounts, cases}`; accepts once and returns lifecycle summary immediately.
- `authz_status`, `authz_stop`, `authz_result`: `{batchId, owner}`.
- Account: `{id, label, role?, tenant?, revision, headers:[{name,value}], probe:{request:{url,method,headers,body}, claims:[{pointer,expected:string}]}}`. Headers are the *complete explicitly selected credential header set*, including Cookie when selected. Probe uses GET, or an explicitly declared read-only POST. Verify JSON claims by exact scalar string representation, not substring/JWT decoding.
- Case: `{id,label,request:{url,method,headers,body},ownerAccountId,readOnly:true,evidence:{object:{pointer,expected:string},protected:{pointer,expected:string}},expectations:[{accountId,expected:'allow'|'deny'}]}`. Both evidence pointers must be distinct and match JSON scalars; protected evidence must be a nonempty application-specific value. HTML/login/GraphQL errors and ambiguous representations are inconclusive.
- `anonymous` is a reserved account reference. It strips the union of all configured credential header names and default Cookie/Authorization/X-API-Key/X-CSRF-Token/X-XSRF-Token. Use the case owner's probe to verify anonymous: 401/403, or explicit null principal claim; never infer anonymous from missing fields/HTML.
- Max 4 real accounts, 10 cases, 100 requests, 300 seconds, 1 request/sec, concurrency 1. Every verification, baseline and confirmation counts. Global exclusivity with injection DAST and PTK analyses. Stop cancels queued work; in-flight response settles within a bound. No auto replay on worker/browser restart.
- Verify owner around legitimate baseline; require object AND protected evidence. Verify comparison identities before and after requests. Repeat unexpected access. Expected 401/403/404 is a result, not global transport failure; expired/mismatched probe, CSRF errors, redirects, GraphQL errors, missing evidence or drift => inconclusive. Do not claim a denied request proves all authorization secure.
- Cell outcomes: `expected_access`, `expected_denial`, `unexpected_access`, `inconclusive`. Unexpected access requires repetition and verified identities. Store bounded evidence signals/matches, status, endpoint, account labels, expected policy; omit raw auth, full bodies and private configured expected values from public output.
- Isolation transport must omit ambient credentials and prevent Set-Cookie from changing the browser jar. Exact selected Cookie can be applied by narrowly scoped DNR request modification; response Set-Cookie/Set-Cookie2 removal. Prove actual Chromium cookie/bearer/anonymous behavior and jar integrity. No redirects, no browser-tab cookie replacement. Fail closed on unsupported transport.

## cert-x management API

`KI_AUTHZ` restricted to providers/providers.html and pages/sidepanel.html, session required. All mutation/execution honors current PTK group/tool policy and workspace exact DAST scope.

- `state`: safe `{accounts,captures,plans,batches,workspace,scope}`. Captures include request ID, method, endpoint (no query values), selectable credential header names and cookie names, and input identities; never values. Reuse DAST capture/list UI controls.
- `save_account`: `{requestId,label,role?,tenant?,credentialHeaders:[names],cookieNames:[names],claims:[{pointer,expected}],readOnly:true,id?}`. Capture is the identity probe and source of selected credentials. Account is workspace-scoped; same-workspace chats may explicitly select it. Re-saving creates a new revision and invalidates pending plans. No password fields.
- `delete_account`: `{accountId}` removes material and stops affected active batches.
- `verify`: `{accountId}` runs bounded verification (approval applies for agent calls).
- `prepare`: `{cases:[{requestId,label?,ownerAccountId,readOnly:true,evidence,expectations,objectSwap?}],budget?}`. Resolve captured request, optional single object replacement, and complete private account snapshots. Freeze account revisions, workspace/scope, case request and expectations; public plan contains references, endpoints, selection and budget, no credentials/expected evidence values. New accounts/scope/expectations require a new plan.
- Optional `objectSwap`: `{location:'path'|'query'|'form'|'json',name,index,value:string}`. Path index counts nonempty segments (zero based), query/form index is captured ordinal, JSON name is pointer and index leaf ordinal. Replace exactly one string/numeric object ID; numeric JSON value is validated numeric token text, preserving type and other bytes. Paths remain in exact origin/scope and reject ambiguous separators/dot segments. Never enumerate IDs.
- `run`: `{planId,planHash}`; final dispatch rechecks scope, policy, account revisions, plan expiry and pending stop after pairing.
- `status`, `stop`, `findings`, `export`: `{batchId}`. Exports reuse completed-download verification and chat/workspace Outputs ownership.
- Tool names: `ptk_list_accounts`, `ptk_save_account`, `ptk_verify_account`, `ptk_prepare_access_test`, `ptk_run_access_test`, `ptk_access_status`, `ptk_stop_access_test`, `ptk_access_findings`, `ptk_access_export`. UI can delete accounts; list tool returns safe state. Status/stop remain available after profile deselection, global Disabled still applies. New authz tools belong to existing PTK group.

UI: `providers/authz.js` exports `initAuthz()`, mounts `#authz-section`, section `authz`, session query. Accounts → requests/objects and expected access → review → run; neutral switches, collapsed advanced mappings. Use existing DAST capture without reconstructing cookies from browser jar. JSON evidence fields are explicit; request read-only declaration is required even for GET. No hidden automatic login or model calls.
